[y=54 x=57 B19.2] 4.3.1 Keys and Integrity Constraints
[y=97 x=68 B10.8] ★ GOLDEN TOPIC
[y=130 x=57 R12.0] A key field is an attribute (or set of attributes) that helps uniquely identify
[y=148 x=57 R12.0] records and link tables together. Understanding keys is essential for designing
[y=166 x=57 R12.0] efficient databases.
[y=267 x=65 B12.0] 1. Candidate Key ( )
[y=288 x=65 R10.8] Any field (or set of fields) that has the potential to uniquely identify a record. A table
[y=304 x=65 R10.8] may have multiple candidate keys, but only ONE is selected as the primary key.
[y=329 x=80 R10.2] Must contain unique values.
[y=344 x=80 R10.2] Cannot contain NULL (empty) values.
[y=360 x=79 R10.2] Example: In an Employee table: EmpID, EmpLicense#, and EmpPassport are all Candidate
[y=375 x=80 R10.2] Keys.
[y=425 x=65 B12.0] 2. Primary Key ( )
[y=446 x=65 R10.8] The one specific field chosen from the Candidate Keys to uniquely identify every
[y=462 x=65 R10.8] record in the table. It ensures no two records are exactly alike.
[y=487 x=80 R10.2] Must contain unique values.
[y=502 x=80 R10.2] Cannot contain NULL values.
[y=517 x=80 R10.2] Each table has ONLY ONE Primary Key.
[y=533 x=79 R10.2] Example: We select EmpID as the Primary Key.
[y=594 x=69 B10.8] 💡 Analogy
[y=616 x=69 R12.0] In a classroom, students have a Roll Number, a B-Form Number, and a
[y=634 x=69 R12.0] Phone Number. All three are Candidate Keys. The school chooses Roll
[y=652 x=69 R12.0] Number as the main identifier, making it the Primary Key.
