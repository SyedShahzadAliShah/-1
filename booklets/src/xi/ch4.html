Chapter 4

Data and Analysis

This chapter teaches you how raw facts become organised information in a database, how tables are linked with keys, how to draw an ER diagram, and how to build tables, forms, queries and charts in Microsoft Access. Banks, NADRA, college libraries and fee offices all run on these ideas.

4.1.1 Data, Information and Database

Data are unprocessed facts, figures or observations. They can be quantitative (numbers: 80, 75, 90) or qualitative (descriptions: the colours of cars in a parking lot). Data on its own is not very useful — a list of marks does not yet tell you whether the class is strong.

When you organise, process and interpret data, it becomes information. Information has meaning and supports a decision. Example: “The class average is 80%, so we can move to the next chapter.”

A database is an organised collection of related data, stored in a structured way so it can be accessed, managed and updated easily. Paper registers and loose files make searching painful; a database is built for search, update and sharing.

Data→Processing→Information→Decision
AspectDataInformation
DefinitionRaw facts and figuresProcessed, meaningful data
Example85, 90, 75Average marks = 83.3%
UsefulnessLittle, on its ownUseful for decisions

Five CS XI marks: 80, 75, 90, 70, 85. Sum = 400. Average = 400 ÷ 5 = 80%. The numbers are data; “the class average is 80%” is information; a Student table holding every student’s marks is a database.

Exam line: Data is raw; information is processed data used for decision-making. Always add one pair of examples.

Do not call a jumble of WhatsApp numbers a database. Related + structured + easy to update is what makes it a database.

ڈیٹا خام حقائق ہیں، معلومات وہی حقائق ہیں جب انہیں ترتیب دے کر معنی دے دیا جائے۔ ڈیٹا بیس متعلقہ ڈیٹا کا منظم ذخیرہ ہے جسے آسانی سے تلاش اور تبدیل کیا جا سکتا ہے۔

1. Is “Nadia, Class 11, 72 marks” data or information?

2. Why is a stack of unmarked answer sheets not a database?

Answers: 1. Data (raw facts about one student). 2. It is not organised in a structured, searchable, updatable collection of related records.

4.1.2 Database Management System (DBMS)

A DBMS is software that lets you create, manage and interact with databases. It sits between the user and the stored files. You never edit raw data files by hand — you talk to the DBMS (Access, MySQL, Oracle, SQLite) and it handles storage, security and consistency.

Advantages you must be able to list:

  • Less redundancy. The department name is stored once, not in every student row.
  • Consistency. Change a phone number once; every screen that uses it shows the new number.
  • Security. Only authorised users see sensitive fields (an admin sees marks; office staff see names).
  • Integrity. Rules stop duplicate roll numbers and empty primary keys.

In a paper register, Ali’s address is written on the admission page, the fee page and the sports page. If he moves house, two of the three pages stay wrong. In a DBMS, Address lives in one Student table. Every form and report reads that single field.

ڈی بی ایم ایس وہ سافٹ ویئر ہے جو صارف اور ڈیٹا بیس کے درمیان پل کا کام کرتا ہے۔ اس سے تکرار کم ہوتی ہے، ڈیٹا ایک جیسا رہتا ہے، صرف مجاز افراد دیکھ سکتے ہیں، اور غلط اندراج رک جاتی ہے۔

1. Name two DBMS programs.

2. Which advantage stops two students sharing the same roll number?

Answers: 1. MS Access, MySQL (Oracle, SQLite also). 2. Integrity (unique / primary-key constraint).

4.2 Database Components (Tables, Records, Fields)

The basic structure is a table (also called a relation): rows and columns, like a spreadsheet, holding facts about one kind of thing (Students, Teachers, Books).

A record (row, tuple) is one complete instance — everything about Ali. A field (column, attribute) is one kind of fact — the whole Name column, or the whole Grade column.

Roll NoNameCourseGrade
101AliCSA
102SaraITB+
103AhmedCSA

The row 101 | Ali | CS | A is one record. The Name column is one field.

Memory: row = record = one person. column = field = one question on the admission form.

Do not mix two entities in one table (students and library books together). Each entity gets its own table; keys will link them later.

ٹیبل قطاروں اور کالموں میں ڈیٹا رکھتا ہے۔ ایک قطار ایک ریکارڈ (مثلاً علی کی پوری معلومات) ہے، ایک کالم ایک فیلڈ (مثلاً صرف نام) ہے۔

1. How many records and how many fields are in the table above?

2. Is “CS” a record or a field value?

Answers: 1. 3 records, 4 fields. 2. A value stored in the Course field.

4.3.1 Keys and Integrity Constraints ★ Golden

A key is a field (or a set of fields) that uniquely identifies records and links tables. Integrity constraints are the rules that keep those keys honest.

Candidate key. Any field (or combination) that could uniquely identify a row. A table may have several. In an Employee table: EmpID, EmpLicense# and EmpPassport are all candidate keys.

Primary key (PK). The one candidate you actually choose. Rules: unique, never NULL, only one PK per table (it may be a composite of two columns). Example: EmpID.

Alternate key. The leftover candidate keys. After EmpID is chosen, EmpLicense# and EmpPassport become alternate keys — still unique, just not “the” identifier.

Foreign key (FK). A field in this table that refers to the PK of another table. It may contain duplicates (many employees in one department) and, in some designs, NULL.

Classroom analogy. Roll Number, B-Form number and phone number can all identify a student (candidate keys). The school picks Roll Number as the primary key. B-Form and phone become alternate keys. In a Result table, RollNo is a foreign key pointing back to Student.

TableFieldRole
StudentRollNoPrimary key
StudentBFormNoAlternate key
ResultRollNoForeign key → Student.RollNo
ResultExamID + RollNoCould be a composite primary key

Board questions: “Differentiate primary and foreign key” (table of 4 points) and “Why can a PK not be NULL?” Because a NULL would mean “this row has no identity”, so the DBMS could not tell rows apart.

A phone number is a bad PK: people change numbers, two siblings may share one, and some students have none (NULL). Roll numbers are issued by the school and stay unique.

کینڈیڈیٹ کی وہ فیلڈ ہے جو ریکارڈ کی شناخت کر سکے۔ پرائمری کی منتخب شدہ شناخت ہے — منفرد اور خالی نہیں۔ جو بچ جائیں وہ آلٹرنیٹ کیز ہیں۔ فارن کی دوسرے ٹیبل کی پرائمری کی کی طرف اشارہ کرتی ہے اور ٹیبلز کو جوڑتی ہے۔

1. Can a table have two primary keys?

2. Can a foreign key have duplicate values?

Answers: 1. No — only one PK (it may be composite). 2. Yes — many child rows may point to the same parent.

4.3 Relational Database Management System (RDBMS)

An RDBMS stores data in several tables and uses primary and foreign keys to keep relationships. Banks, universities and NADRA use RDBMS software. Extra strengths on top of a plain DBMS:

  • Reduces redundancy by splitting data into related tables.
  • Supports many users at once, with permissions.
  • Is queried with SQL (Structured Query Language) — a standard language of SELECT, INSERT, UPDATE, DELETE.

Instead of one giant spreadsheet of students-and-departments, an RDBMS has Department(DeptID, DeptName) and Student(RollNo, Name, DeptID FK). CS is stored once. SQL: SELECT Name FROM Student WHERE DeptID = 1;

آر ڈی بی ایم ایس کئی ٹیبلز میں ڈیٹا رکھتا ہے اور کیز سے ان کے تعلقات برقرار رکھتا ہے۔ ایس کیو ایل سے سوال پوچھے جاتے ہیں۔ اس سے تکرار کم اور کئی صارفین محفوظ طریقے سے کام کر سکتے ہیں۔

1. What language do you use to query an RDBMS?

2. Why split Department out of the Student table?

Answers: 1. SQL. 2. To store the department name once (less redundancy) and update it in one place.

4.4 Entity Relationship Model (ER-Model) ★ Golden

The ER model is the architect’s blueprint: you draw what will be stored and how it connects before you create tables in Access. Three building blocks:

ComponentMeaningSymbolExample
EntityA real-world object we store data aboutRectangleSTUDENT, TEACHER, COURSE
AttributeA property of an entity. PK is underlinedOvalStudentID, Name, Class
RelationshipHow two entities are connectedDiamondEnrolls, Teaches, Has

Cardinality (types of relationship)

TypeMeaningExample
One-to-One (1:1)One record ↔ exactly one record. Rare; often for security.One student has one ID card.
One-to-Many (1:M)One record in A ↔ many in B. The most common type.One teacher teaches many students.
Many-to-Many (M:N)Many in A ↔ many in B.Many students enrol in many classes.

The M:N rule. A relational database cannot store M:N directly — it duplicates data. Break it into two 1:M relationships with a junction table (also called a bridge or associative table). Example: Enrollment(StudentID, ClassID, Date).

Always state cardinality on the diagram (1 and M at the ends of the line). For M:N, the long question is “how do you resolve it?” — draw the junction entity with two foreign keys.

ای آر ماڈل ڈیٹا بیس کا خاکہ ہے۔ مستطیل ہستی، بیضوی صفت، لوزی تعلق۔ تعلقات 1:1، 1:M یا M:N ہوتے ہیں۔ M:N کو دو 1:M میں توڑنے کے لیے جنکشن ٹیبل بنانا پڑتا ہے۔

1. What symbol is used for a relationship?

2. A hospital: one patient, many appointments. Cardinality?

Answers: 1. Diamond. 2. 1:M (Patient 1 — has — M Appointment).

4.5 Referential Integrity ★ Golden

Referential integrity means every foreign-key value in a child table must match an existing primary-key value in the parent — or be NULL if the design allows it. It stops orphan records.

If Result.StudentID is a FK to Student.StudentID, you cannot type Result for student 999 if 999 is not in Student. You also cannot delete student 101 while results for 101 still exist — unless you first handle those child rows.

Cascade operations

Cascade Update. Change the PK in the parent, and every matching FK in the child changes automatically. Ali’s ID 101 → 201 updates Enrollments too. Nothing is left pointing at a vanished 101.

Cascade Delete. Delete the parent, and related child rows are deleted too. If Sara (102) leaves school, her Enrolment and Result rows disappear. That prevents “ghost” marks for a student who is gone.

Before Cascade Update

Student.IDEnrol.StudentID
101101

After changing 101 → 201 with Cascade Update ON

Student.IDEnrol.StudentID
201201

If Cascade Update were OFF, Access would refuse the change, or (in a sloppy file) leave Enrol stuck on 101 — an orphan.

Cascade Delete is powerful and dangerous. Deleting one parent can wipe years of child history. In a real school, you more often archive a student (a Status field) than delete them.

Write: definition, why it matters (no orphans), then one numbered example of Cascade Update and one of Cascade Delete. Mention parent vs child.

ریفرنشل انٹیگریٹی کا مطلب ہے بچہ ٹیبل کی فارن کی ہمیشہ والدین کی موجود پرائمری کی کی طرف اشارہ کرے۔ کیسکیڈ اپ ڈیٹ والدین کی کی بدلنے پر بچوں کو خود بدل دیتی ہے؛ کیسکیڈ ڈیلیٹ والدین مٹانے پر متعلقہ بچے ریکارڈ بھی مٹا دیتی ہے۔

1. What is an orphan record?

2. Cascade Delete: parent Teacher is removed. What happens to that teacher’s Class rows?

Answers: 1. A child row whose FK value does not exist in the parent. 2. They are deleted automatically (if Cascade Delete is on).

4.6 Relational Schema Development

A relational schema is the formal written design of the database: table names, fields, primary keys, foreign keys and how tables relate. You write it before clicking around in Access.

It defines (1) how data is split into tables, (2) which columns each table has, (3) which fields are PK/FK, (4) the relationships. Benefits: less redundancy, integrity planned in advance, easier to grow later.

Written schema for a tiny college:

Department (DeptID PK, DeptName)
Student    (RollNo PK, Name, Class, DeptID FK → Department)
Course     (CourseID PK, Title, Credit, DeptID FK → Department)

Skipping the schema is like building a house without a drawing. You get messy, broken structures that are painful to repair.

ریلیشنل اسکیمہ ڈیٹا بیس کا لکھا ہوا نقشہ ہے: کون سے ٹیبل، کون سے فیلڈ، کون سی کیز، کون سے تعلقات۔ سافٹ ویئر کھولنے سے پہلے یہ بنانا چاہیے۔

1. Name two things a schema must show.

2. Give one reason to write a schema before opening Access.

Answers: 1. Tables/fields and keys/relationships. 2. It reduces redundancy and mistakes (any valid benefit).

4.7 Case Study — Library Management System

A college library needs a database. Walk the seven steps examiners expect.

Step 1 — Requirements. A book has ID, title, author, publisher. A member (student/teacher) has ID, name, contact. A member can borrow many books; a book can be borrowed by different members over time. Record Issue Date and Return Date.

Step 2 — Entities. Book, Member. (Borrowing will need a third entity in step 6.)

Step 3 — Attributes. Book: BookID (PK), Title, Author, Publisher. Member: MemberID (PK), Name, ContactInfo.

Step 4 — Relationship. Member borrows Book.

Step 5 — Cardinality. One member borrows many books over time; one book is borrowed by many members over time → M:N.

Step 6 — Resolve M:N. Add junction entity BorrowRecord: BorrowID (PK), MemberID (FK), BookID (FK), IssueDate, ReturnDate. Now Member 1—M BorrowRecord M—1 Book (two 1:M links).

Step 7 — Final schema.

Member       (MemberID PK, Name, ContactInfo)
Book         (BookID PK, Title, Author, Publisher)
BorrowRecord (BorrowID PK, MemberID FK, BookID FK, IssueDate, ReturnDate)

Sample rows after Sara borrows “Khushwant” on 5 Oct 2026:

BorrowIDMemberIDBookIDIssueDateReturnDate
5001102B-172026-10-05

The same book can later be borrowed by Ali as BorrowID 5002 — no duplicated book title, no duplicated member address.

لائبریری میں ممبر اور کتاب کا تعلق بہت-سے-بہت-سے ہے، اس لیے بورو ریکارڈ نامی پل ٹیبل بناتے ہیں جس میں دونوں کی فارن کیز اور اجراء/واپسی کی تاریخ ہوتی ہے۔

1. Why is BorrowRecord needed?

2. Where do IssueDate and ReturnDate belong, and why not on Book?

Answers: 1. To break M:N into two 1:M links. 2. On BorrowRecord — they belong to a transaction, not to the book itself (a book is issued many times).

A query does not copy the table into a second storage place. It is a saved question. Change the table, re-run the query, and the answer updates.

4.9 Creation of Tables in Microsoft Access

Plan first (4.9.1): purpose, field list, data type of each field, which field is the PK.

Datasheet View (4.9.2) — fast, spreadsheet-like, good for beginners, weak on rules.

  1. Create tab → Table.
  2. A blank grid appears.
  3. Double-click Field1, Field2, … to rename.
  4. Type data; Access guesses the data type.

Limitation: you cannot easily say “Marks cannot exceed 100”. Professionals use Design View.

Design View (4.9.3) — full control before any data is typed.

  1. Create tab → Table Design.
  2. Type each Field Name (StudentID, Name, …).
  3. Pick the Data Type from the dropdown.
  4. Right-click the unique field → Primary Key (key icon).
  5. Save the table.
Data typeUse it for
Short TextNames, addresses, phone numbers (you do not add phone numbers). Up to 255 characters.
NumberValues you calculate with: Age, Marks, Quantity.
Date/TimeDate of birth, admission date, appointment time.
CurrencyFees, salary.
AutoNumberAccess fills a unique sequential number — excellent PK.

Phone numbers look numeric but are Short Text. Leading zeros (0333…) would vanish in a Number field, and you never sum two phone numbers.

پہلے ٹیبل کا منصوبہ بنائیں۔ ڈیٹا شیٹ ویو تیز لیکن کمزور ہے؛ ڈیزائن ویو میں فیلڈ، ڈیٹا ٹائپ اور پرائمری کی خود منتخب کرتے ہیں۔ فون نمبر شارٹ ٹیکسٹ رکھیں۔

1. Best data type for StudentID if you want Access to generate it?

2. Best data type for FeeAmount?

Answers: 1. AutoNumber. 2. Currency.

4.10 Designing Forms for Data Manipulation

A form is the screen people actually type into. It cuts errors and can show validation messages. Every form must have a data source — a table or a query. A form with no source has nowhere to save.

Form Wizard (the exam method):

  1. Create tab → Form Wizard.
  2. Select the table (e.g. Student).
  3. Move fields with > (one) or >> (all).
  4. Choose layout. Columnar = one record at a time, best for data entry.
  5. Name it (“Student Registration”) → Finish.

A Student Registration form shows Student ID (AutoNumber, locked), Full Name, Class, Department as labelled boxes, plus Save. The clerk never sees the raw datasheet and cannot accidentally overwrite the next row.

فارم اندراج کی سادہ اسکرین ہے۔ ہر فارم کسی ٹیبل یا کوئری سے جڑا ہوتا ہے۔ فارم وزرڈ سے ٹیبل چنائیں، فیلڈز منتخب کریں، کالم نما لے آؤٹ بہتر ہے، نام دے کر ختم کریں۔

1. Can a form exist without a table or query?

2. Which layout is best for entering one student at a time?

Answers: 1. No — it needs a data source. 2. Columnar.

4.11 Creating Queries in MS Access ★ Golden

A query retrieves, filters and analyses data without changing the original tables. A simple SELECT query:

  1. Create tab → Query Design.
  2. Show Table → add Student → Close.
  3. Double-click the fields you want; they drop into the grid.
  4. Red Run (!) button executes it.

Criteria restrict rows. Type a value in the Criteria row under a field.

GoalWhere to typeExample
Single criterionCriteria row, one columnDepartment → "Computer Science"
AND (both must match)Same Criteria row, two columnsName "Ali" and Department "Computer Science"
OR (either may match)Criteria row and the or: rowDepartment "IT" or "Computer Science"

Wildcards in Access: * = any characters, ? = one character. Like "A*" finds Ali, Ahmed, Ayesha.

Equivalent SQL (what Access writes behind the grid):

SELECT StudentName, Department
FROM Student
WHERE Department = "Computer Science";

SELECT StudentName, Department
FROM Student
WHERE StudentName = "Ali" AND Department = "Computer Science";

SELECT StudentName, Department
FROM Student
WHERE Department = "IT" OR Department = "Computer Science";

Remember: AND = same row in the grid; OR = different rows. Examiners draw a blank grid and ask you to fill Criteria and or:.

Text criteria need quotes: "IT". Numbers do not: >= 80. Mixing these is a common cause of empty results.

کوئری ٹیبل کو بدلے بغیر سوال پوچھتی ہے۔ ایک شرط Criteria قطار میں، AND ایک ہی قطار کی دو کالموں میں، OR الگ قطار (or:) میں۔ وائلڈ کارڈ * کئی حروف، ? ایک حرف۔

1. Criteria for marks at least 80?

2. You want CS or IT. Same row or two rows?

Answers: 1. >=80 under Marks. 2. Two rows (OR).

4.11.4 Data Summarization and Statistical Analysis

Grouping combines rows that share a value (all CS students together) and then an aggregate calculates a number for the group. In Access click Totals (Σ) to reveal the Total row in the grid.

FunctionWhat it calculates
COUNT()How many records (students in IT)
SUM()Total of a number field (fees collected)
AVG()Mean
MAX() / MIN()Highest / lowest in the group

Average marks per department: add Department and Marks; Totals Σ; Department → Group By; Marks → Avg; Run.

DepartmentAvg of Marks
Computer Science82.5
IT76.0

Check: CS marks 80, 85 → average (80+85)/2 = 82.5. IT 70, 82 → 76.0.

SELECT Department, AVG(Marks) AS AvgOfMarks
FROM Student
GROUP BY Department;

گروپ بائی ایک جیسے ریکارڈ جوڑتا ہے، پھر COUNT، SUM، AVG، MAX، MIN سے خلاصہ نکلتا ہے۔ ایکسیس میں Σ بٹن Total قطار کھولتا ہے۔

1. Which Total setting goes under Department?

2. Which function counts how many books each member has borrowed?

Answers: 1. Group By. 2. COUNT (of BorrowID or BookID) grouped by MemberID.

Chapter 4 Review

Chapter summary

  • Data = raw facts; information = processed data used for decisions; a database stores related data in a structured, updatable way.
  • A DBMS is the software layer that provides less redundancy, consistency, security and integrity.
  • Table = rows (records) and columns (fields). One table, one entity.
  • Candidate keys could identify a row; the primary key is the one you choose (unique, not NULL); leftover candidates are alternate keys; a foreign key points at another table’s PK.
  • An RDBMS keeps several related tables and is queried with SQL.
  • ER symbols: rectangle entity, oval attribute, diamond relationship. Cardinality 1:1, 1:M, M:N. M:N needs a junction table.
  • Referential integrity forbids orphan FKs. Cascade Update copies a changed PK into children; Cascade Delete removes children with the parent.
  • Write a relational schema before building. Library case: Member and Book are M:N, resolved by BorrowRecord.
  • Objects: tables store, forms enter, queries search, reports print.
  • Access Design View sets field names, data types and the PK. Phone numbers are Short Text; money is Currency; auto IDs are AutoNumber.
  • Forms need a table/query source; Wizard + columnar layout for data entry.
  • Query criteria: one value; AND on the same row; OR on two rows. Totals Σ for Group By / Count / Sum / Avg / Max / Min.
  • Bar/column compare categories, pie shows parts of a whole, line shows a trend over time.

Short questions — model answers

  1. Data = raw facts (80, 75, 90). Information = processed meaning (“average is 81.7%, the class is ready”).
  2. Less redundancy, consistency, security (authorised access), integrity (valid, unique keys). (Sharing / backup also accepted.)
  3. Record = one student’s full row (101, Ali, CS, A). Field = one column such as Name.
  4. PK uniquely identifies a row, cannot be NULL, one per table, lives in the parent. FK refers to a PK, may duplicate, may be NULL, lives in the child, creates the relationship.
  5. It would duplicate attributes of both entities. Split into two 1:M links with a junction table that holds both FKs plus extra attributes (dates).
  6. Every FK must match an existing parent PK. Inserting Result.StudentID = 999 is rejected if 999 is not in Student — that would have been an orphan.
  7. Cascade Update copies a changed parent PK into child FKs. Cascade Delete removes child rows when the parent is deleted.
  8. Table stores; form enters; query searches/filters; report prints.
  9. They are identifiers, not quantities; leading zeros would vanish; you never add two numbers of a phone.
  10. Put one value on the Criteria row and the other on the or: row of the same field (or of different fields if that is the question).

Long questions — model answers

  1. Entities STUDENT and COURSE, relationship Enrolls (M:N). Junction ENROLLMENT(EnrollID PK, StudentID FK, CourseID FK, Date). Schema: Student(StudentID PK, Name, Class); Course(CourseID PK, Title); Enrollment as above. Diagram: 1 — M — M — 1 through the junction.
  2. (a) Parent 101 Ali → 201 Ali; child Result rows that said 101 now say 201. (b) Delete parent 102 Sara; all Result and Enrolment rows with 102 disappear. Integrity definition: FK must match a live PK; this stops orphans and keeps reports true.
  3. Follow steps 1–7 in the chapter. Sample: (5001, 102, B-17, 2026-10-05, NULL); (5002, 101, B-17, 2026-10-12, 2026-10-20) — same book, two members, no duplicated titles.
  4. Create → Table Design; enter the five fields and types; right-click RollNo → Primary Key; Save as Student. Create → Form Wizard → Student → >> all fields → Columnar → name Student Registration → Finish.
  5. Grid: Name, Department, Marks. Criteria under Department: "CS" (or "Computer Science"); Criteria under Marks: >=80 (same row = AND); Sort under Name: Ascending. SQL: SELECT Name, Department, Marks FROM Student WHERE Department="CS" AND Marks>=80 ORDER BY Name; Totals query: Department Group By, StudentID Count, Marks Avg.
  6. (i) Column or bar — compare categories (classes). (ii) Pie — each class is a part of one whole enrolment. (iii) Line — a trend over years.
