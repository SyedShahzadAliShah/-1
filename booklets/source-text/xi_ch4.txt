##P73
Database and DBMS
A database is an organized collection of related data that is stored in a
structured manner so that it can be easily accessed, managed, and updated. In
traditional systems, data was stored in files or books, making it difficult to
search. A database solves these problems.
4.1.2 Database Management System (DBMS)
A DBMS is software that allows users to create, manage, and interact with
databases. It acts as a bridge between the user and the database. Instead of
directly handling data files, users interact with DBMS.
Advantages of DBMS:
The same data is not stored multiple
times unnecessarily. E.g., Department
name is stored once, not in every student
record.
Ensures all users see the same correct
data. Updating a phone number once
updates it everywhere.
Allows only authorized users to access
sensitive info. (Admin sees marks, staff
sees only names).
Ensures stored data is accurate and
reliable. (E.g., preventing duplicate Roll
Numbers).

4.3.1 Keys and Integrity Constraints
★ GOLDEN TOPIC
A key field is an attribute (or set of attributes) that helps uniquely identify
records and link tables together. Understanding keys is essential for designing
efficient databases.
Any field (or set of fields) that has the potential to uniquely identify a record. A table
may have multiple candidate keys, but only ONE is selected as the primary key.
Must contain unique values.
Cannot contain NULL (empty) values.
Example: In an Employee table: EmpID, EmpLicense#, and EmpPassport are all Candidate
Keys.
The one specific field chosen from the Candidate Keys to uniquely identify every
record in the table. It ensures no two records are exactly alike.
Must contain unique values.
Cannot contain NULL values.
Each table has ONLY ONE Primary Key.
Example: We select EmpID as the Primary Key.
💡 Analogy
In a classroom, students have a Roll Number, a B-Form Number, and a
Phone Number. All three are Candidate Keys. The school chooses Roll
Number as the main identifier, making it the Primary Key.

An RDBMS stores data in multiple tables and uses keys (like Primary and Foreign
keys) to maintain relationships between those tables. It is powerful, structured,

Reduces data redundancy (duplication).

##P78
Types of Relationships in ER Model
Understanding relationships is essential for designing efficient and accurate
databases. There are three main types:
1. One-to-One (1:1)
One record is related to ONLY ONE record in another entity. This is rare and often used for
security.
Example: One Student has One ID Card.
STUDENT (1) — HAS — (1) ID CARD
2. One-to-Many (1:M)
One record in Entity A relates to MULTIPLE records in Entity B. This is the most common
relationship.
Example: One Teacher teaches Many Students.
TEACHER (1) — TEACHES — (N) STUDENT
3. Many-to-Many (M:N)
Multiple records in Entity A relate to multiple records in Entity B.
Example: Many Students enroll in Many Classes.
STUDENT (M) — ENROLLS — (N) CLASS
⚠️ The M:N Database Rule
Relational databases cannot directly support Many-to-Many relationships.
It causes data duplication. To fix this, we must break it into two 1:M
relationships using a Junction Table (e.g., an "Enrollment" table).

##P79
4.5 Referential Integrity
★ GOLDEN TOPIC
Referential integrity is a fundamental concept that ensures the accuracy and
consistency of data across related tables. It ensures that a Foreign Key in one
table always refers to an existing and valid Primary Key in another table.
Why is it Important?
Imagine a Student Table and a Result Table. The Result table uses StudentID as
a Foreign Key. If Referential Integrity is turned ON:
You cannot enter a result for StudentID "999" if "999" does not exist in the main
Student table. (Prevents orphan records).
You cannot delete a student from the Student table if they still have marks in
the Result table, unless you handle the related records first.

##P80
Referential Integrity Operations
To maintain consistency automatically without manual effort, DBMS provides
two powerful operations.
1. Cascade Update
If a Primary Key value is changed in the parent table, that exact change is
automatically updated in all related child tables.
Example: If Ali's StudentID changes from 101 to 201 in the Student table, his ID will
automatically change to 201 in the Enrollments table. No data is lost or disconnected.
2. Cascade Delete
If a record is deleted from the parent table, all related records in child tables
are also deleted automatically.
Example: If student Sara (ID 102) leaves the school and is deleted from the Student table, all
her records in the Enrollments and Results tables are instantly wiped out. This prevents
"ghost" data from clogging the system.
Benefits of Referential Integrity
Maintains complete data consistency.
Saves time and manual effort for admins.
Reduces errors and prevents orphan
records.
Ensures reliable and accurate reporting.

##P81
4.6 Relational Schema Development
A relational schema is a formal representation of the structure of a database. It
acts as the design or blueprint of the database before it is actually
implemented in software like MS Access.
What does a Schema define?
How data is organized into Tables.
What Fields (columns) each table contains.
Which fields are Primary Keys and Foreign Keys.
How different tables are related to each other.
Why develop a Schema?
Developing a relational schema is an important step because:
1. It reduces redundancy (duplication of data).
2. It improves data integrity by planning keys in advance.
3. It makes the database easier to manage and scale in the future.
👨‍🏫 Teacher's Tip
Remind students that skipping the schema design phase is like trying to
build a house without an architectural drawing. It leads to messy, broken
structures.

4.8 Different Database Objects
In a DBMS, data is managed and presented using different tools known as
database objects. These objects help users interact with the database
efficiently. The four main objects are Tables, Forms, Queries, and Reports.
1. Tables
The most important object; it is where data is actually stored. A table is organized into
rows (records) and columns (fields). Tables are the foundation of a database
because all other objects depend on them.
2. Forms
A Form provides a user-friendly interface for entering and updating data. Instead of
typing directly into scary-looking tables, users use clean forms (like a web registration
page) with text boxes, drop-downs, and buttons. Forms reduce data entry errors.
Page 17

##P87
Database Objects (Continued)
★ KEY CONCEPT
3. Queries
A Query is a request to retrieve specific data from the database. Queries allow you to
"ask questions" of your database. For example: "Show me all students who scored
above 80%." Queries are incredibly powerful because they filter, sort, and calculate
data.
4. Reports
A Report is used to present data in a structured, formatted, and visually appealing
way, usually for printing or sharing. For example, a school generates a printed report
card or a fee summary. You do not enter data into a report; you only read it.
💡 Quick Summary for Students
Tables: Store the data.
Forms: Enter the data.
Queries: Search the data.

4.9 Creation of Tables in MS Access
Creating tables is the fundamental step in developing a database. A carefully
designed table ensures data accuracy, improves query speed, and saves
storage.
4.9.1 Planning the Table Structure
Before touching the software, you must plan:
Purpose: What will this table store?
Fields: What exact columns do I need?
Data Types: Is it Text, a Number, or a Date?
Primary Key: Which field is the unique identifier?
4.9.2 Creating Table using Datasheet View
Datasheet View is the fast, easy, spreadsheet-like way to create tables. It is
great for beginners but offers limited control.
1. Go to the Create tab and select Table.
2. A blank grid appears (like Excel).
3. Double-click the column headers (Field1, Field2) to rename them.
4. Start typing data directly into the cells. MS Access tries to guess the data type
automatically.
⚠️ Limitations of Datasheet View
While fast, Datasheet view doesn't let you set strict validation rules (like
"Marks cannot be over 100") easily. Professional developers prefer Design
View.

##P89
Table Creation (Design View)
4.9.3 Creating Table using Design View
Design View provides full, structured control over your table before you enter
any data. This is the professional way to build tables.
1. Go to the Create tab and select Table Design.
2. Enter the Field Name (e.g., StudentID, Name).
3. Select the exact Data Type from the dropdown.
4. Right-click the field that should be unique and select Primary Key (a small
key icon will appear).
5. Save the table.
4.9.4 Selecting Appropriate Data Types
Choosing the right data type prevents errors and saves memory space.

4.10 Designing Forms
Forms serve as an interface to enter, modify, and view records. They minimize
input errors and enforce validation rules visually.
4.10.2 Identifying the Data Source
Every form MUST be linked to a data source (a Table or a Query). A form cannot
exist without knowing where to save or retrieve its data.
4.10.3 Designing forms using Form Wizard
The Form Wizard provides a guided, step-by-step approach to creating clean
forms.
1. Go to the Create tab and select Form Wizard.
2. Select Table: Choose your data source (e.g., Table: Student) from the
dropdown.
3. Select Fields: Use the > button to move fields you want on the form, or >> for
all fields.
4. Choose Layout: Select how the form looks. Columnar shows one record at a
time and is best for data entry.
5. Name & Finish: Give the form a title (e.g., "Student Registration") and click
Finish.
