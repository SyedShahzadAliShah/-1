1.1.1 Discrete and Continuous Quantities
Discrete Quantities: Separate,
countable items with specific values.
They can be counted one by one.
Number of students in a classroom
Number of cars in a parking lot
Continuous Quantities: Can take any
value within a range. They flow
smoothly without breaks.
Temperature of water
Speed of a moving car
💡 Analogy: Stairs vs Ramp
Stairs represent discrete data (fixed steps). A ramp represents continuous
data (any point).

1.1.4 Boolean Algebra
Boolean algebra (developed by George Boole) deals with only two values: TRUE
(1) and FALSE (0). It is the foundation of digital electronics and computer
programming.
Concept
Description
Example
Variables
Letters that hold values 0 or 1.

1.1.5 Boolean Operations
1. AND Operation ( · )
The AND operation gives output 1 ONLY when ALL inputs are 1.
Expression: Y = A · B
A door with two locks. The door opens only when BOTH locks are unlocked.

##P7
Boolean Operations (Continued)
2. OR Operation ( + )
The OR operation gives output 1 when ANY input is 1.
Expression: Y = A + B
A room with two doors. You can enter if EITHER door is open.
3. NOT Operation ( ' or ¯ )
The NOT operation inverts the input. It is a unary operation (operates on only
one operand). If input is 1, output is 0.
Expression: Y = A' or Y = A̅
A room light switch. When switch is ON, room is lit. When OFF, room is dark.

1.1.13 Karnaugh Maps (K-Maps)
★ GOLDEN TOPIC
A K-map is a graphical tool used to simplify Boolean expressions. It uses a grid
where adjacent cells differ by only ONE bit (Gray code). We group 1s in powers of
2 (1, 2, 4, 8) to simplify equations without complex algebra.
Two-Variable K-Map (Variables: A, B)
Needs 2² = 4 cells.

👨‍🏫 Grouping Rule
Make as large groups as possible (of size 1, 2, 4, 8). Overlapping is allowed.
Variables that change state (0 to 1) within a group are eliminated.

##P16
LogiSim Evolution: Simulation Tool
LogiSim Evolution is a graphical tool for designing and simulating logic circuits. It
allows students to visually build the truth tables and boolean expressions they
learn in theory.
1. The Interface Areas
Menu Bar: Top bar for File, Edit, Project, Simulate.
Toolbar: Quick access to standard tools (Wiring, Poke, AND, OR, NOT gates).
Explorer Panel (Left): Contains component libraries (Gates, I/O, Wiring).
Attribute Table (Bottom Left): Adjust properties of selected gates (e.g.,
Number of Inputs, Facing direction).
Drawing Canvas (Right): The dotted grid where you place and wire gates.
💡 Wiring Colors during Simulation
Bright Green: Logic 1 (HIGH)
Dark Green: Logic 0 (LOW)
Blue: Unknown / Unconnected pin
Red: Error / Short circuit

##P17
Building a Circuit in LogiSim
Step-by-Step: Building Y = A · B
1. Select the AND Gate from the Toolbar or Gates library and place it on the
canvas.
2. Select the Input Pin (square icon with a 0) and place two pins to the left of the
gate (label them A and B).
3. Select the Output Pin (circle icon with a 0) and place it to the right (label it Y).
4. Use the Wiring Tool to click and drag wires from the Input Pins to the AND
gate's input ports. Wires must be horizontal or vertical.
5. Wire the gate's output to the Output Pin Y.
6. Select the Poke Tool (pointing finger) to toggle input A and B between 0 and 1
to test the circuit!

##P21
1.2.4 The Waterfall Model
★ GOLDEN TOPIC
A linear, sequential approach. Each phase must be completed before the next
begins. There is no going back to a previous phase easily.
When to use?
Requirements are clear, fixed, and well-understood.
Project is small to medium size.
Technology is stable.
Disadvantages (Cons)
Advantages (Pros)
Not flexible to changes.
Simple to understand and manage.
Testing happens very late in the process.
Well-documented at every step.
📚 Case Study Reference: Library System
The textbook uses the "Al-Noor Library Management System" as a Waterfall
case study because the requirements were 100% fixed before coding began.
Page 21

##P22
1.2.4 The Agile Model
★ GOLDEN TOPIC
An iterative approach. Software is developed in small cycles called sprints
(usually 2-4 weeks). Customer feedback is gathered continuously.
When to use?
Requirements are unclear or may change.
Customer wants frequent progress updates (early delivery).
Complex or innovative projects.
Disadvantages (Cons)
Advantages (Pros)
Less documentation.
Highly flexible to changes.
Unpredictable end-time and cost.
Early delivery of working software.
📚 Case Study Reference: Mobile App
The "Al-Noor Student Mobile Application" used Agile because teachers,
parents, and students constantly requested new features during
development.

1.3 Communication Models (OSI)
★ GOLDEN TOPIC
A communication model explains how data travels from one device to another
through a network. The OSI (Open Systems Interconnection) Model was
developed by ISO in 1984. It divides communication into 7 layers.
"Please Do Not Throw Sausage Pizza Away" (Bottom to Top: Physical, Data
Link, Network, Transport, Session, Presentation, Application).
